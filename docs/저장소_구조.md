# AMD 저장소 구조

판매수수료 자동계산 및 경영분석 보고서 생성 시스템(AMD, Analysis & Management Dashboard)의
폴더 구조와 각 스크립트의 역할을 정리한 문서입니다.

## 1. 폴더 구조

```
AMD/
├── run.py                    # 전체 파이프라인 진입점
├── common.py                 # 공통 스타일/색상/매장코드 매핑
├── config.yaml                # 프로젝트 설정 (회사명, KPI 계산식, 시즌/분기 정의 등)
├── audit_system.py            # 템플릿 참조·외부 링크 점검 스크립트
│
├── amd_report.py               \
├── arba_process.py              |
├── expense_report.py            |
├── sales_report.py              |  개별 보고서 생성 모듈
├── sales_analysis.py             |  (아래 "2. 스크립트별 역할" 참고)
├── sales_summary.py              |
├── transfer_report.py            |
├── tax_invoice_report.py         |
├── management_report.py          |
├── year_compare_report.py        |
├── history_report.py             |
├── history_update.py           /
│
├── input/                     # 매월 담당자가 채워 넣는 원본 데이터 (git 추적 제외)
├── output/                    # 생성된 보고서 결과물 (git 추적 제외, output/YYYY-MM/ 하위 폴더 포함)
├── DB/                        # 월별손익DB.xlsx (누적 손익 데이터베이스)
├── backup/                    # DB 갱신 전 자동 백업본
├── templates/                 # 보고서 서식 템플릿 (xlsx)
├── docs/                      # 운영 기준 문서 (이 파일 포함)
│
├── 실행.bat                    # run.py 실행
├── 보고서만생성.bat             # history/management/year_compare 리포트만 재생성
├── 전년대비보고서만생성.bat      # year_compare_report.py만 재생성
├── DB업데이트만.bat             # history_update.py만 실행
│
├── CLAUDE.md                  # Claude Code용 프로젝트 메모 (git 규칙, 알려진 버그 등)
├── README.md / CHANGELOG.md / LICENSE.md / CONTRIBUTING.md
└── requirements.txt
```

`input/`, `output/`, `backup/`, `DB/월별손익DB.xlsx`는 `.gitignore`로 git 추적에서
제외되어 있습니다 (각 폴더의 `.gitkeep`만 추적됨). 즉 실제 매출/급여 데이터나 생성된
보고서 바이너리는 저장소에 올라가지 않고, 로컬/서버에만 존재합니다.

## 2. 실행 흐름

1. `실행.bat` (또는 `python run.py`) 실행 → 정산 월(YYYY-MM) 입력
2. `run.py`가 `input/` 폴더에서 파일명 패턴(glob)으로 그 달의 원본 파일들을 찾아 읽음
3. 급여/공제/매출 계산 후 `amd_report.py`, `arba_process.py`, `expense_report.py`,
   `sales_report.py`, `sales_summary.py`, `transfer_report.py`, `tax_invoice_report.py`를
   차례로 호출해 `output/YYYY-MM/` 아래에 보고서 생성
4. `sales_analysis.py` 결과(매출집계_분석.xlsx)를 바탕으로 `history_update.py`가
   `DB/월별손익DB.xlsx`를 갱신 (갱신 전 `backup/`에 자동 백업)
5. 갱신된 DB를 바탕으로 `history_report.py`, `management_report.py`,
   `year_compare_report.py`가 경영진용 분석 보고서를 `output/` 루트에 생성

`보고서만생성.bat`/`전년대비보고서만생성.bat`/`DB업데이트만.bat`은 위 흐름 중 일부만
다시 실행하고 싶을 때 사용합니다.

## 3. 스크립트별 역할 / 입력·출력

### run.py — 파이프라인 진입점
- 입력: 사용자가 콘솔에 입력하는 정산 월(YYYY-MM), 그리고 아래 각 모듈이 필요로 하는
  `input/` 파일 전체
- 출력: 없음 (각 하위 모듈 호출로 위임)

### common.py — 공통 모듈
- 다른 모든 스크립트가 `from common import ...`로 사용하는 색상 팔레트, 스타일 헬퍼
  함수(`st`, `bdr`, `set_col_widths`), `STORE_CODE_MAP`/`CODE_TO_STORE`/`ONLINE_CODE_MAP`
  (매장명 ↔ 매장코드 매핑)를 정의
- 입력/출력 파일 없음 (라이브러리 모듈)

### amd_report.py — 판매수수료작업시트(AMD)
- 입력: `input/사원마스터.xlsx`, 영업 판매 파일(`input/영*판매*.xlsx`),
  `input/급여상여명세서_*.xlsx`, `output/YYYY-MM/아르바이트_정산서.xlsx`,
  템플릿 `templates/판매수수료작업시트_AMD_템플릿.xlsx`
- 출력: `output/판매수수료작업시트_AMD.xlsx`

### arba_process.py — 아르바이트 급여 자동 취합
- 입력: `input/사원현황_일용직_YYYY-MM.xlsx`, `input/급여상여명세서_일용직_YYYY-MM.xlsx`,
  `input/월별근태_일용직_YYYY-MM.xlsx`
- 출력: `output/YYYY-MM/아르바이트_정산서.xlsx`

### expense_report.py — 경비지원 및 공제 집계
- 입력: `input/★*경비내역서*.xlsx` (직배비, J열), `input/◈*매장공제건*.xlsx`
  (덜받음/임의사은품·대체할인/POS공제), `input/*재고실사*공제건*합계*.xlsx`
  (유통하자 LOSS)
- 출력: `output/경비지원및공제_집계.xlsx`

### sales_report.py — 매장별 매출집계
- 입력: `sales_data`(사전 계산된 매출 딕셔너리, run.py에서 전달), 매니저/소득구분 매핑
- 출력: `output/YYYY-MM/매출집계.xlsx`

### sales_analysis.py — 매출집계(분석)
- 입력: `run.py`에서 전달되는 정산 결과, `input/영*판매*.xlsx` 계열 파일
- 출력: `output/YYYY-MM/매출집계_분석.xlsx` (이후 `history_update.py`가 이 파일을
  DB 갱신 소스로 사용)

### sales_summary.py — 판매수수료집계
- 입력: 정산 결과, `output/YYYY-MM/아르바이트_정산서.xlsx`,
  템플릿 `templates/판매수수료집계_템플릿.xlsx`
- 출력: `output/판매수수료집계.xlsx`

### transfer_report.py — 중간관리 판매수수료 이체내역
- 입력: `input/매장전화요금내역.xlsx`, `input/급여상여명세서_*.xlsx`,
  `input/*로젠*고객직배*.xlsx`, `output/아르바이트_정산서.xlsx`
- 출력: `output/중간관리판매수수료이체내역.xlsx` (openpyxl로 직접 생성, 템플릿 미사용)

### tax_invoice_report.py — 세금계산서 출력
- 입력: `input/중간관리매장_매입세금계산서_기재사항정보.xlsx`,
  템플릿 `templates/세금계산서출력_템플릿.xlsx`
- 출력: `output/세금계산서_YYYYMM.xlsx`

### management_report.py — 경영분석보고서
- 입력: `DB/월별손익DB.xlsx`, `input/매장구분_행사_신규_폐점_YYYYMM.xlsx`
  (동일/신규/폐점/행사 매장 분류 기준)
- 출력: `output/경영분석보고서.xlsx` (Dashboard 포함 13개 시트, 차트 2개)
- 참고: 2026-07-08에 헤더 행 오프셋 버그를 수정함 (`CLAUDE.md` 참고)

### year_compare_report.py — 전년대비 판매수수료/손익 보고서
- 입력: `DB/월별손익DB.xlsx`, `input/매장구분_행사_신규_폐점_YYYYMM.xlsx`
- 출력: `output/판매수수료_전년대비보고서.xlsx` (Dashboard + 피벗값 시트 구성)

### history_report.py — 연도/분기/시즌별 손익분석
- 입력: `DB/월별손익DB.xlsx`
- 출력: `output/연도별_분기별_시즌별_손익분석.xlsx`

### history_update.py — 월별손익DB 갱신
- 입력: `output/YYYY-MM/매출집계_분석.xlsx` (2026-06분부터), 기존 `DB/월별손익DB.xlsx`
- 출력: 갱신된 `DB/월별손익DB.xlsx` (갱신 전 상태는 `backup/월별손익DB_before_*.xlsx`로 자동 백업)
- 규칙: 2026년 5월까지는 기존 DB 수치를 그대로 보존, 2026년 6월부터 매출집계_분석.xlsx로 갱신.
  같은 년-월 + 매장코드 조합은 기존 행을 삭제 후 새 자료로 교체

### audit_system.py — 시스템 점검
- 입력: 코드 내 템플릿 참조, `templates/` 폴더 실제 파일, 주요 xlsx의 외부 링크 여부
- 출력: 콘솔 점검 결과만 출력 (파일 생성 없음)

## 4. 템플릿 파일 (templates/)

| 템플릿 | 사용 스크립트 | 생성 결과 |
|---|---|---|
| `판매수수료작업시트_AMD_템플릿.xlsx` | amd_report.py | output/판매수수료작업시트_AMD.xlsx |
| `개별통지문_템플릿.xlsx` | run.py | output/YYYY-MM/개별통지문.xlsx |
| `판매수수료집계_템플릿.xlsx` | sales_summary.py | output/YYYY-MM/판매수수료집계.xlsx |
| `세금계산서출력_템플릿.xlsx` | tax_invoice_report.py | output/세금계산서_YYYY-MM.xlsx |
| `판매수수료_연도별DB_전년대비_기존양식_참조.xlsx` | (참고용, 코드에서 직접 읽지 않음) | - |

`transfer_report.py`(이체내역서)는 템플릿을 쓰지 않고 openpyxl로 직접 생성합니다.

## 5. 설정 파일 (config.yaml)

- 회사명/프로젝트명, 버전 정보
- `paths`: input/output/backup/db/templates/docs/logs 폴더 경로
- `database`: 월별손익DB.xlsx 파일명, 2026-05까지 보존·2026-06부터 갱신 규칙
- `kpi`: 수금율/원가배수/경비율/영업이익율/순이익율 계산식 정의
- `store_class`: 매장구분(동일/신규/폐점/행사) 값과 파일명 패턴
- `season`/`quarter`: 시즌(SS/FW) 및 분기 구간 정의

## 6. 관련 문서
- `CLAUDE.md`: git 작업 규칙, 브랜치 보호 정책, 알려진 과거 버그 기록
- `docs/` 하위 번호가 매겨진 txt 문서들: 버전별(V4~V8) 점검 결과 및 운영 기준 이력
